# 🛡️ AI Cyber Risk Prediction

An AI-powered cybersecurity risk prediction system that estimates the **Attack Probability (AP)** of software vulnerabilities by combining vulnerability intelligence from NVD, EPSS, and CVSS metrics.

The project focuses on building a machine learning pipeline for predicting whether a vulnerability is likely to be exploited, helping security analysts prioritize remediation efforts.

---

## ⚙️ Features

- Automated bulk CVE intelligence collection from Wazuh CTI.
- Extraction of collected CVE JSON records into a unified CSV dataset.
- CVE data preprocessing and cleaning.
- Merge CVE information with EPSS scores.
- Feature engineering for vulnerability prediction.
- XGBoost-based Attack Probability prediction.
- Model evaluation using multiple performance metrics.
- Export trained model for deployment.
- Predict risk for new CVE records.

💻 Usage

1. Fetch Vulnerability Data from Wazuh CTI

Collect CVE information in bulk from Wazuh CTI.

The input can be:

- `.txt` file (one CVE ID per line)
- `.csv` file (contains a `cve_id` column)

> **Note:** Future versions will automatically retrieve Vulnerability Detection data directly from the Wazuh Manager, replacing the current `cve_list.txt` testing file.

Windows (PowerShell)

```powershell
python cti_collector.py --input "cve_data/List_CVE_ID.csv" --outdir "cve_data/json_data" --workers 40                                   
```

Linux / macOS

```bash
python "./CTI Collector/cti_collector.py" \
    --input "./CTI Collector/cve_list.txt" \
    --outdir "./CTI Collector/cve_data"
```

Features

- Automatic retry mechanism
- Multi-threaded downloading
- Resume interrupted downloads
- Duplicate CVE detection
- Bulk CTI collection

---

2. Extract CVE Data to CSV

After collecting the enriched CVE JSON records with `cti_collector.py`, use `Extract_CVE.py` to parse and flatten all JSON files into a single CSV dataset ready for preprocessing and training.

```bash
python Extract_CVE.py "cve_data/json_data" --out "ket_qua_full.csv" --cve-list "cve_data/List_CVE_ID.csv" --include-missing --workers 64
```

**Arguments**

| Argument | Description |
|---|---|
| `input_dir` (positional) | Path to the directory containing collected CVE JSON files (e.g. `cve_data/json_data`). |
| `--out` | Path to the output CSV file (e.g. `ket_qua_full.csv`). |
| `--cve-list` | Path to the reference CSV/TXT file listing the expected CVE IDs (e.g. `cve_data/List_CVE_ID.csv`), used to cross-check extraction completeness. |
| `--include-missing` | Include rows for CVE IDs listed in `--cve-list` but not found in the JSON directory, marking their fields as missing/empty instead of skipping them. |
| `--workers` | Number of parallel worker threads/processes used to read and parse JSON files (e.g. `64`). |

> **Tip:** Increase `--workers` on machines with more CPU cores to speed up extraction of large CVE datasets, but reduce it if you encounter I/O bottlenecks or memory pressure.

---

3. Train the Machine Learning Model

Run the training script:

```bash
python train.py
```

> Replace `train.py` with your actual training script if different.
